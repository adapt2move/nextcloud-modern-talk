## BPR1-01 — Medium: frame-count limits leave native media allocation bounds undecided

**State: open. Owner: separately delegated media/platform and architecture contributor, with performance review.** Affects Q.PERF-05, Q.PERF-01/02 accounting and mandatory bootstrap handoff items 1/5/6. Exact candidate locations: [ADR-002](../architecture/decisions/002-deep-modules.md), lines 38–54, especially media row 51; [ADR-004](../architecture/decisions/004-policy-media-lifecycle.md), lines 64 and 72–78.

**Static reproduction/preconditions:** consider a future otherwise-qualified call with only one subscribed screen, no queue backlog beyond the allowed two frames, and a format/resolution whose decoded backing is larger than the native memory envelope. The declared count limits still hold. For a simple arithmetic example, one 16,384 × 16,384 four-byte surface is 1 GiB before padding or decoder references. This is not an observed negotiated stream or a measured allocation; it demonstrates that frame count alone does not establish a byte bound. An oversized native frame can arise before it reaches the two-entry presentation queue.

**Expected:** the bootstrap's concrete resource contract gives the media owner a finite admission/allocation limit, including native decode/capture buffers and in-use/shared surfaces, and specifies the response before an oversized allocation. **Actual:** the contract selects two queued frames per stream, 100 ms queued audio, four remote cameras and one screen per call. It does not choose maximum frame backing bytes/dimensions/formats, an aggregate native surface/pool byte ceiling, or an equivalent bound covering allocations outside those queues. The image-cache caps are not stated to cap media pools. GPU/footprint acceptance targets are measurements to qualify later, not an allocation admission rule. Audio duration likewise does not state the admitted stream/format or aggregate buffer ceiling.

This leaves a consequential resource decision for implementation after the gate, despite Q.PERF-05 requiring concrete bounds for expensive paths. It is not a claim that the unconfigured diagnostic consumes excessive memory or that any provisional budget is infeasible.

**Required correction:** define a finite native media allocation contract now: an admitted profile/format/dimension and stream limit, or aggregate byte/pool bounds that cover decoder/capture/reference/in-flight/renderer-held surfaces and audio buffers. Assign the owner, checked size arithmetic, pre-allocation rejection, overload/degrade/stop behavior and generation-change reclamation. Reconcile local preview, camera-plus-screen and two-call concurrency. A smaller delivered profile must remain a distinct workload; do not silently lower quality to pass the original baseline. Actual engine implementation and Mac measurements remain later work.

**Acceptance:** an independent static derivation can bound the selected profile's maximum controlled buffer allocation and explain rejection of an oversized frame before allocation. The designated verifier may add proportionate contract checks if new size/admission primitives are introduced; this review requests no native benchmark at `G.BOOT`. Update the affected ADR and IST without changing feature status. Author response/remediation commit: **none supplied**. Dynamic reproduction/recheck: **not run**; finding follows from the absent limits in the exact contract.

## Performance assessment

Non-media work has useful concrete limits: eight accounts, two active calls, bounded intent/control queues with independent stop flags, ordinary and reserved request slots, capped decoded control bodies, paged history, finite outgoing bodies, streamed transfers, bounded caches, search replacement and provider worker caps. Boundary values reject oversized UTF-8 text before copying and reject page overflow. The generic `Page<T, N>` is not itself a byte guarantee for arbitrary `T`; the actual renderer rows use fixed-size identities/enums and bounded text. The current diagnostic's one snapshot is bounded. Task construction/polling is required to be nonblocking, frames bypass chat snapshots, and stale work has cancellation/generation ownership. Runtime enforcement remains absent and correctly labelled.

The policy schedule uses `F/R/D/S/E = 15 s/10 s/3 s/2 s/250 ms`; `S + R + D = F`, and leases expire 13 s after request start. Seven five-read rounds give at most 35 starts/minute/call. The stated 46 KiB round estimate gives 322 KiB/minute, approximately 43.96 kbit/s combined. The 512 KiB/minute envelope is approximately 69.91 kbit/s combined. These consume part of the audio target of 0.2 Mbit/s in each direction; directional totals, signaling, TLS, retries, relay and in-flight overrun remain counted. One policy timer wake/s and 0.5% of one logical CPU per call are allowances to measure, not demonstrated spare capacity. No active-call polling is charged to signed-in idle. Qualification failure or a cost conflict suspends the affected path or requires reviewed profile/budget revision; it does not relax freshness. I found no arithmetic exemption or claimed measured feasibility in this schedule.

The workload contract assigns strict schema parsing, fixture hashes, deterministic schedules, exact counts, cache/residency and search mix to the lab owner, with typed application and delivered-stream observations from application/media owners. Two independent reconstructions precede measurements. Counts, directions, codecs/layers, moving video/speech, screen role and quality windows must validate throughout the actual run. Missing evidence is incomplete, and lighter media/activity is invalid for the original profile. Sender and receiver screen profiles retain camera load. These are appropriate QR1-05 bootstrap decisions; they are not an approved executable workload.

The collector contract covers prelaunch through final exit, short-lived/nested/reparented helpers, birth identity/PID reuse, crash/kill paths, startup/teardown and gaps. One-second aggregate footprint p95 and sampled maximum remain separate from lifetime high-water evidence. `U`, the sum of all lifetime maxima, is correctly a conservative upper bound, not a measured simultaneous peak; an excessive loose bound needs a qualified tighter bound, and missing evidence cannot become zero. GPU/shared/system-service attribution and overlap remain explicit. Qualification includes a 100 ms touched burst, 300 ms helper, breach detection and collector overhead. Header declarations were independently checked in the pinned [Apple task header](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/osfmk/mach/task_info.h) and [resource header](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/sys/resource.h); they do not prove target-OS access, abnormal-exit retrieval or complete GPU peaks. The contract correctly blocks a native memory pass if that qualification is unavailable.
