## Product finding dispositions

### PR1-01 — Verified fixed: restrictive invariants and precedence

[CONV-003/004](../product/conversations.md#conv-003) now defines parameter merge → server invariants → current gates → actual returned-room reconciliation. A classified request with conflicting forced public/listable/SIP values cannot be presented as unrestricted success; an unrelated object binding is rejected. Known restrictions also govern edits, and a contradictory response blocks the affected action pending reconciliation.

The rule table makes channel all-role call denial and moderator-only member lists explicit. Announcement member leave denial and its editable all-message notification default are separate. Preserved deletion/history/guest-access/listability locks and owner-controlled preservation are distinguished from classified automatic retention. [CONV-010](../product/conversations.md#conv-010) specifies the moderator keep transition to `classified_persist`, preserving classified restrictions and message-expiry policy. Editable webinar/presentation/voice defaults are not treated as invariants. Additional native cache/excerpt/export restrictions are explicitly client policy.

[CALL-009/010](../product/calls.md#call-009) resolves the verified classified/global-required-consent exception without authorizing recording or bypassing other gates. Unknown/conflicting classification and unexpected consent refusal require reconciliation. F-027–032/115 and [CT-005](../compatibility/test-matrix.md#ct-005), CT-013/018/027 now exercise the original counterexamples, retention/keep races and ordinary required-consent cases. No remaining objection to this correction.

### PR1-02 — Verified fixed: effective re-ring authority

[MOD-002](../product/moderation-and-integrations.md#mod-002), F-133 and [CT-016](../compatibility/test-matrix.md#ct-016) consistently require effective `START_CALL`, eligible calls, current active participation and an eligible target. An ordinary member can qualify; moderator status alone grants nothing. The [source discrepancy](../compatibility/baselines-and-sources.md#re-ring-authorization-and-response-discrepancy) records both the moderator-only prose conflict and the already-in-call successful no-op.

Acceptance includes an allowed ordinary member, denied/revoked start permission, caller outside/ended call, wrong-room/unsupported targets, already-in-call, DND and federated/transport uncertainty. Success is not delivery proof, and an uncertain request cannot cause an automatic ringing loop. The product requires established active participation; it does not claim the controller's nullable-session/proxy paths universally prove that condition. Released-profile response checks remain integration obligations. No moderator-only client restriction remains.

### PR1-03 — Verified fixed: native poll Close action

[CONTENT-006](../product/files-and-content.md#content-006), F-087 and [CT-010](../compatibility/test-matrix.md#ct-010) require the accessible native Close action itself as author and moderator. They deny an ordinary voter without that authority, apply current access/lobby gates, and handle concurrent/already-closed and lost-response outcomes through authoritative state reconciliation.

Confirmed closure disables voting/Close, retains the poll's message/share and displays only permitted results. Failed refresh remains uncertain; an open poll offers a deliberate, freshly authorized retry. Published closure, draft deletion and message deletion are distinct despite the DELETE verb. Merely displaying a poll closed by another client can no longer satisfy the feature. No remaining objection.

## Mandatory bootstrap handoff

These are unresolved **`G.BOOT` obligations**, not specification defects or authoring-stage runtime failures. The architecture owner must make them concrete and obtain the separately attributable reviews required by [Q.VER-01/02](../quality/verification.md#qver-01--ordered-gates) before full implementation:

1. **Deep Modules and traceability:** assign consequential decisions to owners with narrow public interfaces, dependency direction, typed account/host/room/actor identities, state/error/cancellation contracts and test seams. Map the feature/CT/quality IDs to those interfaces. Keep credential, transport, policy, cache and media responsibilities out of GPUI views; define bounded queues/caches/background work.
2. **Credential durability:** specify stage/activate/resolve/reconcile/exact-generation-delete operations, serialized account transitions, atomic nonsecret metadata and crash ordering. Establish writer settlement, old-item preservation, committed restoration eligibility, durable session-only suppression and truthful residual cleanup. Define Keychain qualification and future-OS unavailability boundaries without inventing a secret-bearing fallback.
3. **Account loss:** define evidence that confirms account rejection versus action/session errors; own admission closure, generation invalidation, cancellation fan-out and local media shutdown. Choose a finite numeric device-release deadline and observable failure path independent of remote leave or durable-metadata success.
4. **Policy freshness:** map authoritative routes/fields and host scope for both families and supported signaling profiles. Approve finite `F/R/D/S/E` and capture-release bounds, propagation/cache assumptions, conservative source time, earliest expiry, sleep/wake and suspension/recovery rules; periodic reads must satisfy `S + R + D <= F`. Account for refresh/retry bytes and wakeups. An unavailable or unbounded required source blocks the affected path/support claim.
5. **Native/media and protocol boundaries:** choose/pin the native engine and FFI/resource ownership; define platform permission/accessibility/capture adapters and truthful unsupported outcomes. Supply test seams for direct-accept cancellation/join-can-start-call atomicity, voluntary prejoin, consent/E2EE and reconnect intent. Define response/reconciliation fixtures for preset invariants, re-ring and poll closure against exact research/release profiles. Source checks do not discharge later interoperability proof.
6. **Performance evidence design:** assign the frozen workload schema/replay/actual-profile validator and complete process-lifetime/peak collector interfaces and qualification plan. Preserve separate screen sender/receiver profiles, startup/teardown coverage and conservative peak accounting; provisional budgets remain targets. Real workload reconstruction, collector qualification and Mac measurements belong to subsequent acceptance runs.

Before product/release claims, implementation and verification owners must run the applicable cases with real native adapters/media and exact disposable server profiles, declare tested patch/OS bounds, qualify optional backends, and update current-state/feature evidence.
