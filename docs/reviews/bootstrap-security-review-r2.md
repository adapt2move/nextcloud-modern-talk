## BSR1-01 — High: verified fixed for the identity seam

**Original finding and impact:** the [round-1 security finding](bootstrap-security-review-r1.md) and BAR1-01 describe one defect. With uncertain attempted N and retained P, the port could not explicitly select session-only or cancel-and-retain; cold recovery required an already validated runtime; post-rejection suppression used the cancelled runtime context. Original locations were `ports.rs` lines 60–64/90–114 and ADR-003's authority/transition rules at the old candidate. Expected: required choices and recovery/shutdown work remain expressible under appropriate authority. Actual then: implementing the promised behavior required an undocumented side channel or interface redesign. No current credential exploit was alleged.

**Owner/correction:** identity/architecture contributor; author response in **d11d99131d63e5fded7de6e0a7f6c7fb8f473913**, preserved through the final candidate. Independently rechecked [identity.rs](../../crates/talk-core/src/identity.rs), lines 77–399; [ports.rs](../../crates/talk-core/src/ports.rs), lines 93–134; [ADR-003](../architecture/decisions/003-credential-lifecycle.md), especially lines 35–77 and 90–96; and ADR-002's supervisor/resource rules.

| Original counterexample / independent static reproduction | Actual corrected contract and remaining runtime proof |
| --- | --- |
| Start login or restore before any runtime exists | `attempt(PendingAttemptContext, …)` and `restore(RecoveryContext)` require no runtime. Reserved IDs grant nothing; current canonical validation and committed exact eligibility precede issuance. `resolve(OperationContext)` retains authenticated admission. Real Login Flow, item lookup and activation remain absent. |
| Uncertain N → deliberate session-only | Supervisor `Abandon(SessionOnly)` atomically records exact-N abandonment/cleanup and account-wide Suppressed, covering N/P/older items. N=P, wrong P and cross-account runtime references are rejected by the constructor. Actual P binding/admission/validity remains an owner obligation. Atomic Eligible(P) plus N cleanup returns no runtime; cold activation subsequently uses restore. Plain Cancel cannot infer retention or create a session-only receipt. |
