## BAR1-01 — High: verified fixed for the identity contract

Original finding, shared with **BSR1-01**: the old seam could not select uncertain-N session-only or deliberate cancel-and-retain-P, demanded an already validated runtime for cold recovery, and coupled post-rejection suppression to the cancelled runtime. Expected behavior was explicit durable choices under appropriate pre/post-runtime authority. The impact was a required interface redesign or undocumented side channel, not an observed leak. Original locations, reproduction and correction requirements remain in [architecture round 1](bootstrap-architecture-review-r1.md#bar1-01--high-identity-lifecycle-is-not-representable-through-its-declared-seam) and [security round 1](bootstrap-security-review-r1.md).

| --- | --- |

| Account loss after runtime cancellation | `maintain(MaintenanceContext, MaintenanceCommand)` has supervisor-owned authority, no runtime/caller cancellation token and no runtime result. The four methods form one decision-owning identity service, not four facade services. The supervisor has **eight descriptors/account**, seven ordinary plus reserved coalesced suppression, **one provider operation/account and two provider workers globally**. Its context uses checked addition for a **3,000 ms** slice, rejecting overflow and wrong account/epoch/time in its admission predicate. Slice expiry does not settle a writer, free a hung worker slot or authorize a retry loop. Root shutdown retains unresolved durable obligations. These are finite contracts, not implemented queues or timers.

The receipt and admission types intentionally do **not** prove supervisor ownership, durable commit, latest revision, current-attempt registration, valid P or canonical identity. Public synthetic `CommittedRestoration`/report fields can be fabricated in tests; the private owner must enforce those preconditions. `matches_live_attempt` alone is insufficient authorization. This limitation is explicit in code and ADRs, and every concrete method still returns `Unconfigured`. The six new identity tests and two adapter tests exercise the appropriate narrow predicates/absence; they do not simulate a successful journal, Keychain, crash recovery or drop race.

**Disposition: verified fixed for BAR1-01's representability/authority defect; no remaining architecture objection.** BSR1-01 is the same seam and receives architectural concurrence, not a separate security approval. Identity/runtime implementation owners retain durable serialization, provider settlement, actual drop/cancellation and native V.AUTH.STORE/LOSS qualification; the independent security/functional reviewers own their conclusions. No exception or cancellation-as-consent shortcut is accepted.
