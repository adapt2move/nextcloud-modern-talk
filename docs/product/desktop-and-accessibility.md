# Desktop behavior, accessibility, and resilience

These requirements define desktop behavior and accessibility. macOS is the primary product target; available packages and platform qualifications are described in [current state](../status.md) and the [known limitations](../limitations.md). Server notification/presence/settings facts are referenced in [sources S03, S05, S08, S15](../compatibility/baselines-and-sources.md#protocol-sources).

## DESK-001

**Native desktop shell (P1).** Provide account switcher, conversation sidebar, message/content area, contextual details, settings, and discoverable call controls. Preserve navigation context and drafts when resizing or opening a thread. Narrow windows must still provide navigation and an accessible leave-call action. A future compact/floating call window (P4) must retain account identity, mute/leave/share-stop controls, focus behavior, and the same media session; it is not a claim of universal OS picture-in-picture support. macOS window/menu conventions and system-browser handoffs are native integrations, not HTML surfaces.

Acceptance: the application can complete login, find a conversation, send a permitted message, and reach settings without a WebView. Mock/demo data is visibly marked and cannot be mistaken for a live account. Layouts do not hide actionable error states behind decorative overlays.

## DESK-002

**Notifications and privacy (P1 messages; P2 calls).** Request OS notification permission in context. Combine room notification levels, call-notification preferences, server notification state, OS Focus/Do Not Disturb, and local sound choices without claiming control over OS delivery. Default lock-screen content is privacy-preserving; user-enabled previews remain subordinate to sensitive/classified rules. Prevent duplicate banners/sounds from multiple transport paths.

Provide four independent local banner/sound groups: normal messages; important notices (another participant entering a conference call the account belongs to, and personal server message reminders); incoming direct calls; optional Calendar notifications. Keep conference participation and message reminders as distinct typed reasons. Room membership changes alone do not mean someone joined a call; suppress the current user's own join and coalesce participation bursts. Calendar defaults off and requires verified authenticated notification-source availability. Incoming calls retain their own lifecycle and delivery capacity under ordinary-message overload. Message, important and Calendar banners apply while minimized; incoming-call banners may also appear in the foreground without taking focus.

Every category, including Important and Incoming calls, uses ordinary OS Focus/Do Not Disturb control for both banners and sound. Do not request critical/time-sensitive bypass or use a separate notification audio player. OS-managed sound depends on notification-daemon support; Linux independent sound-only delivery is explicitly unavailable when no portable Focus-safe route exists. Native macOS UserNotifications actions require a live app-bundled helper and an admitted current-call dispatcher. With unconfigured media, Accept remains unavailable; no stock CallKit call screen is claimed. A category Test checks local policy/helper delivery only and grants no account, Calendar or call authority.

Use distinct fixed sounds for outgoing ringback, incoming ringing and message notifications, selected from existing openly licensed sound collections or clients with their attribution preserved. Message notifications should be brief and discreet. No sound picker or custom-tone setting is required. The incoming-call category Test and the one-shot speaker check use the same incoming ringtone, without creating a call. Sound assets do not authorize a call or change notification suppression and cancellation rules.

Acceptance: a denied OS notification permission shows guidance while in-app unread/ringing state still works. Notification activation opens the correct account/room/message; deleted or inaccessible targets show unavailable. No background fetch marks content read. A stale call notification is revalidated before acceptance; foreground/background acceptance shares [CALL-001–003](calls.md#call-001). If notifications cannot arrive while the app is quit, say so explicitly; do not promise background delivery until an actual tested mechanism exists.

## DESK-003

**Presence and status (P1 read; P3 editing).** Display supported server user status, custom status text/emoji/expiry, profile/avatar, and call participation separately. Allow supported status/profile/avatar settings only through their core or advertised temporary-avatar APIs and current limits, without overriding server/OS intent silently. Keep read receipts, typing privacy, notification mute, and presence as distinct preferences. Honor session inactive state when content is not actively being read.

Acceptance: unavailable presence is unknown rather than offline. Going offline does not claim the user's status changed server-side. Reconnection re-fetches status; expiry follows server-confirmed time. Choosing Do Not Disturb does not claim to mute every other client automatically.

## DESK-004

**Preferences with clear ownership (P1; advanced P3/P4).** Distinguish device-local settings from server/account settings. Cover theme/system appearance, text scaling, list density, language, send key, sounds, message/call notifications, privacy, attachment destination, cache controls, media defaults/devices, supported backgrounds, and call layout limits. The preference owner tracks pending, confirmed and failed writes; routine saving and autostart setup text is omitted from settings. Unsupported controls are omitted or explained. Launch at login defaults to enabled for a new preferences file; migration preserves an explicitly saved disabled value.

Acceptance: changing an account preference does not alter another account. Server-enforced values remain visible and locked. A failed write visibly restores confirmed active/displayed state, explains the failure and offers explicit Retry; a stale load or failure cannot replace a newer confirmed or pending revision. Only a non-authoritative retry draft retains a failed choice. Disk work stays off the UI thread in one bounded writer with request/revision correlation and atomic replacement. Notification choices for all four groups persist across process restart. Migration copies each old banner/sound choice into messages, important notices and incoming calls, preserving disabled choices; Calendar stays off. Source availability and OS permission/delivery state are transient observations, never inferred from a successful preference save. Device-local language choices are System (default), English, Deutsch and Español. System matches the OS preferred-language list against en/de/es, with English fallback. Explicit choice persists through application-owned preferences; changing language preserves the current account, call, draft and focus. Camera/microphone default preferences never authorize capture while ringing. Removing an account does not erase intentionally saved downloads.

Accounts live in Settings, with nullable authoritative account/server labels, connection state, add/restore/logout actions and independent storage/recovery status. An optional quick switcher defaults to Auto and appears with multiple admitted accounts; saved disconnected records never count as admitted. Boolean settings use switches and notification categories share a compact Banner/Sound table. Successful and pending writes do not leave routine status copy. Failures remain visible with rollback and explicit Retry. Each account has a small remove action that confirms removal from this app, with Cancel focused by default; removal never claims to delete the NextCloud user account.

Privacy checks microphone, camera and screen-sharing permissions without capture. Offer explicit Request and system-settings actions only where supported, and permit chat without any grants. Interactive setup follows the sequential request policy below. Screen-picker consent applies to one share. Devices entry starts microphone monitoring only after a matching permission check; leaving Devices, switching accounts/windows or changing selection waits for disposed/Stopped acknowledgement before fresh capture. Camera preview is explicit. Each selector has a refresh action, a visible chevron, keyboard option navigation and an inline resolved device name for System default. The microphone shows its input-level meter after access is allowed. Output check is an adjacent icon that plays one built-in ringtone, without an output meter; busy and unavailable reasons remain accessible through its tooltip. Camera preview starts from an explicit button inside an empty 16:9 area and stops through an overlaid icon; actual frames fit their aspect ratio within that area. Compact permission errors and inline system-settings/recheck actions appear only when access needs attention; grants do not add success or test-active copy. Device preferences never imply a permission grant or live capture.

After login, present optional permission setup as three sequential steps: microphone, camera, then screen sharing. Entering this interactive sequence authorizes one supported native request on each step, after a fresh read-only check. Show a short purpose sentence and OS-specific explanation, then advance automatically only after observing a grant. Returning to a step never repeats its prompt. Denied, restricted, unknown and unavailable states retain truthful system-settings, recheck and skip actions. No onboarding request starts capture or preview. Users can enter chat without grants and return through Settings; Windows and Linux per-share consent remains per-share. Before a macOS screen request or settings handoff, durably save one account-bound resume marker with a 24-hour lifetime. After relaunch, consume that marker, recheck without prompting, and show a concise ready screen with actual permission states. Clear it on normal completion, reset or removal of that account; another account cannot consume it.

When macOS access is missing, show contextual, native-looking guidance beside the affected microphone, camera or screen-sharing control. Use a clear icon, short purpose statement and numbered steps through System Settings → Privacy & Security → the relevant permission. Distinguish a first request, denial, administrative restriction and an unavailable check. Offer **Allow access** only for a supported first request, **Open System Settings** where supported, and **Check again** after the user returns. Opening settings never marks access as granted; only a fresh permission observation can do that. Mention restarting only where the platform requires it. Keep the guidance readable in light/dark appearance and at 200% text size, with English, German and Spanish copy; it is app guidance, not an imitation system permission prompt.

## DESK-005

**Keyboard and assistive technology (P1 onward).** All shipping actions are keyboard reachable with visible focus and meaningful accessible names, roles, values, and status announcements. Native GPUI integration must expose an accessibility tree verified with macOS VoiceOver. Focus enters dialogs predictably, remains within modal interactions, and returns to the invoking control. Announce new content without continuously interrupting reading.

Acceptance: VoiceOver and keyboard-only users can add an account, change conversations, compose/edit/reply, use menus, handle permissions/errors, accept/decline a direct call, join/leave a conference, choose devices, and stop screen sharing. Icon-only controls have names; keyboard shortcuts never fire while composing IME text. Escape/cancel behavior cannot accidentally end a call or discard a draft without its defined action. A screenshot of an accessible-looking interface is not evidence of accessibility.

## DESK-006

**Readable visual and motion behavior (P1).** Support system light/dark appearance, increased contrast, reduced motion, and text scaling. Do not convey unread, muted, recording, permission-denied, or connection state by color alone. Keep critical controls visible at larger text sizes and small windows. Use contrast and target-size criteria from the quality plan, measured on actual native rendering.

Acceptance: reduced motion removes nonessential animation without hiding progress. At 200% text size, core workflows remain available without text covering their controls. Selection/focus and disabled/error states stay distinguishable in both palettes. Animated images/reactions do not force autoplay when reduced motion or user preference disables it.

Use one consistent Lucide icon set for application actions, retaining upstream attribution; product branding remains separate. Every icon action has a localized styled tooltip and keyboard-accessible explanation. Hover and selection transitions are brief and settle completely; idle windows do not redraw to animate a static control. Unknown system motion preferences use reduced motion until an observation is available.

Application and conversation settings share the same dialog frame, navigation alignment, page-title hierarchy and section spacing. Tabs place the icon before the label. Group related controls under concise headings; separate destructive actions and confirmations. Keep routine saving/saved text out of both dialogs, while showing loading, failure and uncertain outcomes when the user needs to act.

Use the bundled Google Sans family for the runtime interface, retaining its upstream license and exact source attribution. System fallback remains available for missing glyphs. Historical design assets keep their original typography and attribution.

The conversation header stays above the scrolling history with a frosted-glass, theme-aware surface: content passing behind it is genuinely blurred, while titles, actions, focus rings and tooltips remain sharp and readable. macOS and Linux use the native renderer effect; Windows uses an opaque white header with contrasting dark text and icons while its renderer lacks backdrop blur. The effect follows the current content during scrolling and needs no continuous redraw while idle. Rows hidden beneath the header cannot receive pointer actions or count as visible read content; search and keyboard focus reveal their targets below it. Wrapping at larger text sizes must preserve the reading anchor, composer space and delayed end-follow behavior.

Use decorative motion for control feedback and newly opened dialogs, settings pages and small contextual surfaces. Input, focus, semantic state and hitboxes take effect immediately. Closing a dialog, updating progress, receiving a message or remounting a virtualized row must not restart unrelated animation. Typing, IME composition, manual scrolling, media frames and incoming-call presentation remain immediate. Newly appended message bubbles use the bounded entry behavior in MSG-001; delivery state is never delayed by decoration. Reduce Motion preserves the same final visuals without decorative transitions.

## DESK-007

**Offline and reconnect (P1 messaging; P2 media).** Show account-specific offline/stale state and last successful synchronization where useful. Permit reading policy-approved cached content and composing drafts. Do not silently queue permission-changing/destructive actions or automatically send newly composed offline text. On reconnect, refresh credentials/session, capabilities, room membership/policies, and content before making actions available.

Acceptance: one offline account does not block another. Duplicate events reconcile; missing events trigger bounded full refresh. A room removed while offline cannot accept a queued send. Server `modifiedSince` is not treated as a deletion feed: periodic/full reconciliation handles deletion/disinvite. Call recovery follows [CALL-014](calls.md#call-014), with no automatic unmute or resurrection of ended calls.

## DESK-008

**Sleep, app lifecycle, and conflicts (P1/P2).** Closing a window, quitting, logging out, system sleep, and crashing have distinct effects. Explain active calls/transfers/drafts before explicit quit where interruption matters. Do not claim that a closed window disconnected a background account. A crash restart restores only permitted persisted state and never resumes capture automatically.

Acceptance: wake revalidates server session and OS devices; stale notifications and call attempts cannot reconnect blindly. One session becoming obsolete does not delete another device's account. Quit ends local capture and transient session credentials; server-scheduled messages/reminders remain server-owned.

## DESK-009

**Actionable errors and redacted diagnostics (P1).** Use concise user language with retry/change-settings/relogin/leave where appropriate. Provide optional diagnostic details containing client version, supported server versions, resolved feature states, and redacted error categories. No primary passwords, app passwords, cookies, poll tokens, private URLs, room passwords, SIP PINs, message text, or full participant lists belong in default diagnostic export. Follow [security.md](../quality/security.md).

Keep an automatic, rotating local event log for chat connection changes, history requests and send outcomes. Record only typed scalar facts and process-local correlation numbers. A bounded background writer owns the private files; logging failure and overload never block chat. Locations and retention are documented in the [installation guide](../install.md#local-diagnostics).

Acceptance: user-visible errors do not contain raw backend dumps. Export is deliberate and reviewable; redaction is tested with synthetic secrets. No telemetry/analytics or diagnostic upload occurs by default. Native integration, performance, and reliability statements cite measured evidence, not design goals.

## DESK-010

**Locale, time, and platform conventions (P1).** Provide the complete application UI in English, German and Spanish (en/de/es), including typed errors, hints, native action and accessibility names, notifications, dates/times/numbers and plurals. Support Unicode/bidirectional text. User-authored messages, user and room names, and protocol identifiers are not translated. Use stable server IDs independent of translation. Present schedules, reminders, meeting times, and timestamps with the relevant timezone and explicit handling of ambiguous local times. Use platform shortcut names, including Command on macOS.

Acceptance: deterministic checks cover resource/key completeness, placeholders, locale selection/fallback, formatting and plural cases in all three locales. Live language changes preserve interaction state; different UI languages do not change protocol payload identifiers. A right-to-left message does not spoof the surrounding actor/account identity. Date-only, relative-time, and DST transitions are tested with deterministic clocks. No hard-coded mock identity, company, or private server appears in shipped UI.

## DESK-011

**Application updates and OS scope.** Report the actual client version and use this project's GitHub Releases for the selected stable or prerelease channel. Check automatically at a randomized daily time and on explicit request from Settings. Persist the schedule across restarts and download a matching newer package in the background with bounded storage and network work. A verified, installable update exposes a small **Update** action in the top application bar.

Hide the update action while a call or conference is ringing, being joined, active or ending. Recheck the authoritative application state when it is activated, block new call admission during the transition, and drain work before installing and restarting. Never end a call implicitly to update. Revalidate the exact staged package; replace the complete application bundle where applicable, and use the native package manager for a system-managed installation. Failure must preserve a usable installation, explain the outcome and offer a deliberate recovery action.

Distribute macOS releases as a self-contained application in a styled disk image with a clear drag-to-Applications layout. Include the native media runtime and required plugins inside the app; users must not install a separate GStreamer SDK or runtime. Keep a complete app ZIP for the updater, with the same bundled libraries, resources and notices. Installation must not depend on the build machine's framework paths or a package manager. State signing, notarization and supported OS/architecture limits accurately.

Acceptance: checks cover schedule persistence, channel/version/target selection, interrupted downloads, integrity failure, stale staged data, call-admission races and installation rollback. A package without a supported install route is not shown as ready. No executable is downloaded or run from a chat message or server-supplied update URL. A server “upgrade required” response explains the need without bypassing it or treating it as an authentication failure. Source availability or successful cross-compilation is not labeled platform support; signing, notarization and native OS behavior retain their actual qualification limits.
