# ADR-002 — Three architectural layers, decision-owning modules

This document defines ownership and dependency direction across three architectural layers. The [workspace](../../../Cargo.toml) contains five packages; [current state](../../status.md) records implementation and qualification limits. Q.SEC-01/02, Q.PERF-05 and Q.VER-02 govern changes to these boundaries.

## Graph and public surface

`talk-core` is the pure domain package. Its only external dependencies are the pinned CommonMark parser and URL value parser used by the bounded user-text owner; neither performs I/O. The independent `nextcloud-talk-api` package owns HTTP/WSS and typed Talk protocol operations, including HPB; it depends on neither core nor GPUI. `talk-adapters` depends on both and owns application authority, identity, policy normalization and media integration. The composition layer contains the `talk-bootstrap` headless diagnostic and the `talk-desktop` GPUI application. Desktop composes core, adapters and native platform services; presentation modules recursively import only `talk_core::ui`, GPUI/native presentation helpers and local view types. [ADR-007](007-nextcloud-transport.md) describes the protocol boundary. No generic event bus, plugin framework or feature-per-crate split is introduced. Sharing a crate does not permit bypassing the documented private ownership.

| Module / owner | Small public interface | Complexity and data kept private |
| --- | --- | --- |
| Core domain / application owner | Typed local identities, bounded display values, `DesktopPort::{try_submit,take_snapshot}`, worker service ports | Account actor registry, intent validation, use-case ordering, cache indexes, delivery reconciliation, policy source aggregation and snapshot projection |
| Core policy / application owner | `Gate`, conservative `Lease`, typed decision/reason and `CallSession` consuming normalized observations | Capability/config/effective-permission precedence, dependency of each action on sources, consent/call binding and earliest expiry; no renderer recomputation |
| Core user-text owner | `markup::{parse,web_destination}` and bounded `Text`/`Page` document records, also exposed through `ui::markup` | CommonMark parsing, source/display spans, safe user-authored web destinations and finite fallback; no authenticated route, external fetch, HTML execution or OS handoff |
| Identity / adapter owner | `AccountConnection` with typed commands, bounded snapshots and completions; separate pending, recovery, authenticated and supervisor authority | Browser Login Flow, canonical origin/user binding, pending secrets, qualified vault operations, durable journal, provider status mapping and replacement serialization |
| Talk protocol / API owner | Semantic `Client` requests/replies and typed meeting, signaling and HPB interfaces | Endpoint construction, HTTP/OCS/DAV decoding, cookies/session tickets, TLS/origin validation, transport bounds and signaling envelopes |
| Nextcloud / adapter owner | `NextcloudPort::request` with bounded application requests and normalized replies | Account authority, room-token/actor mapping, policy interpretation, application correlation and reconciliation, native call orchestration |
| Native media/platform / adapter owner | Scoped `MediaService`, `CaptureHandle` and received `VideoImage` values; platform permission/device ports | Device and permission lifetime, WebRTC/codec stack, keys, native handles, bounded media buffers, publication enforcement and OS lifecycle |
| Presentation / native UI owner | Bounded `ViewSnapshot`, typed `UserIntent`, `SubmitError`, and explicit data-only exports through `ui`; additive native `ui::presentation` screen/intent contract plus the retained diagnostic consumer | GPUI entity/window/focus/accessibility/layout objects, frame presentation handles and UI localization; no secrets, route construction or backend ownership |
| Composition / runtime owner | Construct explicit adapters and supervisors, start/stop root lifetime | Executor choice, native adapter wiring, account worker lifetimes, platform clock and process accounting registration |

`talk_core::protocol` contains bounded worker DTOs without routes, credentials, cookies or signaling envelopes. `NextcloudClient` implements the typed port; [desktop account composition](../../../apps/desktop/src/composition/accounts.rs) connects it through `AccountConnection` and the identity runtime. The headless bootstrap retains unconfigured diagnostic ports. See the [private identity/transport seam](../nextcloud-contract.md). The diagnostic `IdentityPort` references pending login IDs without exposing credential material. `attempt(PendingAttemptContext, AttemptCommand)` needs no runtime; `restore(RecoveryContext)` can run at cold start; `resolve(OperationContext)` requires live authenticated admission; `maintain(MaintenanceContext, MaintenanceCommand)` has independent bounded supervisor authority and returns no runtime grant. Network authentication consumes an adapter-private origin/account/runtime binding with zeroizing owned app credentials and shared cancellation. The binding is never returned to core/UI. The identity owner supplies it only after committed eligibility and canonical-account validation; the default-off Linux fixture constructor is not shipping authentication. `PolicyInputs` is a fixed-size source bundle: account validity, host configuration, local grid, room/effective permissions/recording, connected session and signaling profile each retain separate observation/lease provenance. It is never complete call authority by itself: the resolver must check sources, current session continuity, user consent and actual native encryption. The [core call state](../../../crates/talk-core/src/calls.rs) applies these checks for the supported native path; unsupported profiles remain unavailable. New operations must extend a cohesive owner and trace to a requirement, not become catch-all string requests.

## Invariants, errors and ownership

| Module | Invariants and failure/lifecycle contract | Test seam |
| --- | --- | --- |
| Core/application | Conversation unifies chat/files/call; presets and user groups are not new room types. Account and host scope every room/cache; `CallScope` adds runtime and call generation. IDs are local nonsecret handles; the future allocator must use OS randomness and reject collisions. A handle alone cannot authorize I/O. One serialized actor per account checks admission and rejects old completions. Shutdown never waits for the renderer. | Pure gate/admission checks now; later deterministic actor scheduler and injected ports. Product CT cases remain future. |
| Policy | Unknown is not false-by-default permission. Known restriction wins; only a fresh complete conjunction can allow. Server role/version names alone grant nothing. Restrictive observations invalidate before snapshot publication; old callbacks cannot renew leases. `Denied`, `Unknown`, `Stale` stay distinct. | Inject source provenance and monotonic epochs; lease tests now; source/event/precedence matrix later. [ADR-004](004-policy-media-lifecycle.md). |
| Identity | Runtime/attempt/vault generations are distinct. Only committed eligible metadata plus accessible confirmed item can restore. Session-only, cancel and deliberate retention of named P are separate choices. No overlapping account replacement; abandoned cleanup cannot delete retained older item. Cancellation is not settlement; dropping an observer task cannot drop accepted ledger/provider work. Errors include operation, provider/category and redacted native code inside this owner; core/UI gets allowlisted category/recovery state only. | Scripted provider and journal fault points, then actual signed macOS Keychain qualification. [ADR-003](003-credential-lifecycle.md). |
| Nextcloud | Validate account/host/runtime before dispatch and callback delivery. Never forward a local app password to a remote host. Encoded bodies are capped before accumulating or decoding them, structure insertion has a shared budget, and automatic decompression is disabled. Underlying HTTP/TLS implementation buffers remain finite library-owned allocations; they have not been performance-qualified. A successful HTTP response is not durable-message or media success. Retry ambiguity requires reconciliation; errors are scoped action/session/account/transport evidence. | Frozen wire fixtures and disposable both-family servers, slow/malformed/cross-host responses; `NextcloudPort` double. |
| Media/platform | No capture on ringing. Mandatory permissions/consent/security before media admission. Frames and RTP bypass core's serialized snapshots. Account loss/expiry closes publication locally; stop owns device release and cannot be cancelled by the very account shutdown it completes. Unconfirmed release is failure, never “devices off.” | Timestamped stop observer and independent device/packet probe; controllable worker hangs, native permissions and termination. [ADR-004](004-policy-media-lifecycle.md). |
| Presentation | `PrepareConference` opens voluntary prejoin; `AcceptDirect` bypasses that interstitial, with all mandatory gates retained. No UI method blocks, polls a future, parses network data or does disk/vault/media work. UI drop detaches a window, not an account's running call; explicit root quit closes all accounts. | Snapshot/intent consumer and future native keyboard/accessibility tests. No HTML timing substitution. |

`Task` is a standard-library boxed `Send` future used at worker seams; it selects no executor. Construction and polling must be nonblocking; blocking OS calls move to bounded dedicated workers. `OperationContext` carries a validated runtime scope, deadline and cancellation for protocol requests and authenticated identity resolution; adapters check it before dispatch and after completion. It is not a preauthorization token or maintenance authority. Identity pending/recovery contexts carry their own deadline/cancellation without a runtime. `MaintenanceContext::for_supervisor(account, operation, now)` gives one 3 s dispatch/observation slice with no runtime/caller cancellation token; expiry retains unresolved work and never proves writer settlement. All four identity methods perform bounded admission before returning an observation task. Accepted work remains owned by the identity supervisor if that task is dropped; no activation may result from a dropped/cancelled attempt/recovery observer. Durable receipts are separate from requested choices and provider observations. See ADR-003 for exact signatures, acknowledgement checks and revalidation obligations. `PortError` contains only category, account reference and retry guidance. No provider message, URL, body or secret is propagated to the renderer. A `Busy` intent was not accepted; future UI must keep the user's input. An accepted intent means queued locally, not server success.

Account shutdown order is admission closure → generation invalidation/cancellation → media publication closure → priority local teardown → asynchronous durable suppression/cache cleanup and bounded remote leave. Credential replacement cancellation may preserve the older account runtime according to ADR-003; do not reuse account-loss shutdown for that narrower event. Root shutdown joins/terminates all owned workers, observes release, flushes permitted durable state and records unresolved cleanup. Other accounts remain independent. Process death is not a vault settlement oracle.

## Usable renderer data boundary

Presentation imports only `talk_core::ui`. That module explicitly reexports `bounded::{LimitExceeded, Page, Text}`, `identity::PersistenceState`, `policy::Decision`, `ids::{AccountId, AccountScope, CallGeneration, CallScope, ConversationId, HostId, RuntimeGeneration, VaultGeneration}`, and the bounded pure `markup` module. The markup records use `Text`/`Page`; their user-authored web destinations grant no application or transport authority. No worker port, secret, authenticated route, media frame or native surface is exported. The ID constructors only import local nonsecret handles; a view cannot authorize an operation by inventing one. `DesktopPort` remains the sole UI service seam. Views may match all persistence/policy cases, name every nested snapshot/intent type and construct bounded display values through that one surface; they do not recompute policy.

The architecture guard compares explicit export paths to this exact vocabulary and checks simple/nested grouped imports by their underlying paths. It rejects aliases, globs and unsupported import grammar at these two inspected boundaries, rather than depending on one import spelling. Direct standard growable container identifiers are forbidden in `ui.rs`, including qualified `Vec`, `String`, `Box`, `VecDeque`, `LinkedList`, `HashMap`, `HashSet`, `BTreeMap`, `BTreeSet`, `BinaryHeap`, `PathBuf`, `OsString`, `CString` and `Cow`. Worker/secret/frame names, raw routes, adapter dependencies and hidden target edges remain forbidden. UI modules/macros that generate uninspected types require a reviewed checker change.

This is a conservative lexical source guard for the inspected files, **not a Rust sandbox, type resolver, macro expander or proof of transitive bounds/information flow**. Its comment/string and import handling is deliberately narrower than Rust syntax; raw/Unicode identifiers, generated indirection and transitive aliases require parser-aware/human review. It does not certify arbitrary aliases or code outside the inspected boundary; allowed data definitions must be reviewed when changed. The compiler and a positive renderer fixture must substantiate the usable export surface. Keep all five original forbidden-edge/container/route negatives plus the directly named `BTreeMap` regression; also challenge unreviewed exports and grouped worker imports. Unsupported source syntax can produce conservative false positives and needs explicit review, not a spelling workaround.

## Concrete resource contract

These are selected runtime limits, not measured performance results. Implementation and qualification limits belong in [current state](../../status.md). Increasing a resource limit needs IST/contract/performance review. Each resource owner must expose nonsecret depth/age/eviction/overflow counters.

| Resource | Bound and overload/cancellation rule |
| --- | --- |
| Accounts and calls | At most 8 configured accounts, 1 publishing call per account, 2 call/prejoin slots application-wide and at most 1 slot/helper per account. Explicit preview consumes its account slot; preview-to-call reuses it. Further previews/joins return `Busy`; do not evict an existing call or bypass unreclaimed old resources. Targets may expand after measured review. |
| UI intents | 64 per window; nonblocking try-send. Coalesce navigation/typing, reject overflow visibly. Leave/logout use a separate one-bit priority signal per account and never wait behind ordinary intents. |
| View snapshots | One latest slot per window, at most 100 conversation rows (256-byte labels) and 100 message excerpts (4 KiB each). Text counts UTF-8 bytes. Durable events live in the owner, not in replaceable snapshots. |
| Account worker | 128 ordinary control records/account, ≤8 KiB each; nonreplaceable overflow invalidates/reconciles the affected stream or closes admission. Restriction/stop signals use separate priority flags, never silent drop. |
| Network | 4 ordinary requests/account, 8 globally; additionally 5 reserved policy/probe requests per active call (coalesced sources). Control body ≤256 KiB decoded, ≤64 nesting levels, ≤4,096 scalar entries; reject oversize before unbounded expansion. One policy refresh/source outstanding. No service is enabled until required limits fit its protocol. |
| Message history/search | 50 messages/page, ≤4 resident pages/account plus visible projection; full individual message ≤128 KiB local hard cap subject to smaller server limit. One search/account, newer search cancels older. Larger supported content needs an explicit chunked/bounded path; no hidden truncation of the message itself. |
| Outgoing message intents | 64 intents/account and 512 KiB encoded total; reject overflow without evicting accepted work. Eligible ordinary intents commit to private account storage before the editor clears. Restricted/session-only intents stay in memory. Persist a dispatch marker before network effects; uncertainty uses bounded read-only reconciliation without replaying ambiguous writes. Attachments remain outside this queue. [MSG-003](../../product/messaging.md#msg-003) owns action behavior. |
| Transfers | 2 active/account, 4 globally; 256 KiB streaming chunk, queue of 16 descriptors/account. Cancellation closes streams and cleans owned temporary files; no body-sized buffering. |
| Caches | Decoded image cache 32 MiB process-wide; native GPU image cache 64 MiB; disk cache 256 MiB/account with policy-based expiry. Classified/sensitive exclusions override these maxima. These are sub-budgets, not a total-memory claim. |
| Ordinary chat storage | 100 room metadata/count records/account, eight histories of at most 100 timeline messages and 50 pin references/excerpts each; 4 MiB per history record, 8 MiB serialized histories total, 16 MiB database. Observations expire after 30 days or earlier policy expiry; queued intents have no cache TTL. [AUTH-009](../../product/accounts.md#auth-009) owns eligibility, private-file access and purge. |
| Media | 2 waiting application-handoff camera/screen frames per stream across formats; the separately charged native ScreenCaptureKit source queue is fixed at 3. At most 100 ms aggregate queued audio per stream across encoded/jitter/PCM waiting stages. [Allocation contract](../media-allocation.md) bounds formats, dimensions, capture/codec/reference/in-flight/shared/GPU backing, compressed bytes, audio/history and auxiliary pools. A Rust media supervisor owns one application-wide ledger spanning both helpers and renderer leases; no private overflow pool. Controlled buffers ≤572 MiB/slot and ≤1,144 MiB/two slots; auxiliary ≤128 MiB/helper + 8 MiB watchdog is separate and unproved. Reclaim only after native references and GPU fences settle; obsolete generations remain charged. Drop replaceable waiting frames or stop on overload. No frame copying through `ViewSnapshot`; no measured footprint claim. |
| Vault/metadata | 1 provider operation/account, ≤2 provider workers globally, 8 descriptors/account (7 ordinary and 1 reserved coalesced suppression slot); OS prompt outstanding blocks another prompt. No unbounded retry queue: overflow rejects new work. Local cancellation closes admission before queueing; suppression cannot wait behind ordinary work. Each supervisor dispatch/observation slice is ≤3 s; uncertain native writes may outlive it, occupy their bounded worker slot and remain ledger-tracked. Timeout/drop never frees that slot by pretending settlement; recovery retries on explicit user/provider/startup triggers with no prompt loop. |

The maintained engine, device and teardown boundaries are in [ADR-005](005-native-media.md). Policy scheduling/cost and frame subscription limits are in ADR-004; complete process accounting includes all these owners under the [measurement contract](../measurement.md). Type bounds do not by themselves establish native allocation or watchdog behavior.

## Integration boundaries

[ADR-007](007-nextcloud-transport.md) and the [integration contract](../nextcloud-contract.md) define the network scope. Internal and HPB media admission is owned by the account/call runtime; unsupported signaling and encryption profiles remain unavailable. The GPUI text widget owns local bounded editing only; its `input.rs` clipboard exception requires explicit draft privacy admission. GPUI 0.2.2 returns an owned clipboard string before the widget can size-check it, so the transient native clipboard allocation is not bounded by our API. Loading a message into the editor requires an explicit edit action and current scoped edit permission. Backend projections must keep `draft_clipboard = Unknown` until restrictive privacy policy is resolved.
