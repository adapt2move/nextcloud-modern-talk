# ADR-004 — Bounded policy authority and local media lifetime

This contract defines policy authority and local media lifetime. COMP-003, CALL-003/006/009–014, Q.SEC-09/10, Q.PERF-04/05 and V.POLICY.FRESH are normative. The [core call state](../../../crates/talk-core/src/calls.rs), [call runtime](../../../crates/talk-adapters/src/nextcloud/meeting_runtime.rs) and media owner implement the supported path; [current state](../../status.md) records its limits. The bounds below remain verification requirements, not universal runtime guarantees.

## Authority and source qualification

The core application policy owner aggregates normalized observations, scoped to account, canonical conversation host, room, runtime and call generation. `nextcloud-talk-api` owns route decoding and protocol observations; the Nextcloud adapter owns policy normalization, full refresh and provenance; the runtime owns monotonic scheduling; media owns enforcement. Only the complete required conjunction at its earliest source expiry can authorize a call or publication. A `PolicyInputs` source bundle or single `Gate` is not that complete decision. Unknown values are explicit; missing observations cannot be synthesized as authority.

Definitions: `C` is `GET /ocs/v2.php/cloud/capabilities?format=json`; `R` is `GET /ocs/v2.php/apps/spreed/api/v4/room/{token}`; `K` is `GET /ocs/v2.php/apps/spreed/api/v4/call/{token}`; `S` is `GET /ocs/v2.php/apps/spreed/api/v3/signaling/settings?token={token}`; `A` is the account probe from ADR-003. All paths are resolved beneath the validated installation base, including its path. They are private protocol mappings, never renderer commands. `C` fields below are beneath `ocs.data.capabilities.spreed`; other OCS data is beneath `ocs.data`.

| Enforced property | NC34/Talk24 authoritative mapping | NC35/Talk25 authoritative mapping | Scope / consequence |
| --- | --- | --- | --- |
| Call support/configuration | `C.features` (`audio`, `video`, `conversation-v4`, `signaling-v3`, required permission/consent features); `C.config.call.enabled` | Same mappings, with added capability-gated attributes | Host authority for nonlocal features/config. Unknown disables join/publication. Missing Talk must not be mistaken for invalid credentials. |
| Membership, effective join/start/publish permissions, lobby/read-only | `R.permissions`, `participantType`, `readOnly`, `lobbyState`, `attributes`; `K` confirms intended current session in connected participants | Same, plus classified/channel/announcement rules from known attributes | Use returned effective permissions; bits 2/4/8/16/32/64 are start/join/ignore-lobby/audio/video/screen. Role is not a substitute. `R.sessionId` alone is only a precheck. |
| Recording policy/state | `C.config.call.recording`, `recording-consent`; `R.recordingConsent`, `callRecording`, `callStartTime` | Same, with verified classified consent exception | Required consent is explicit and bound to call/policy generation. Missing state is unknown. A timestamp is not a unique call ID. |
| Classification/invariants | `R.attributes` with recognized capability-backed semantics; unknown restriction bits block affected actions | Same; classified bit 4, channel bit 8, announcement bit 16; `objectType` corroborates `classified`/`classified_persist` | Conflicting/unknown classification blocks joining; never infer ordinary status from a newer server's omitted field. Channel disallows calls for all roles. |

Both-family pinned capability emitters, settings/config accessors, room response definitions, call controllers and signaling routes were inspected; see [A-SRC-02/03](../source-evidence.md#a-src-02--both-family-policy-sources). The `attributes` mapping uses `ResponseDefinitions.php` as well as docs; prose alone does not cover all fields. `C` is a public endpoint, so authentication is separately checked. For federation, use the **actual** `features-local`/`config-local` lists to choose local versus conversation-host authority; local credentials never go to that host.

**Source profile qualification is mandatory.** Neither the inspected PHP code nor HTTP `no-cache` proves bounded database/cache/cluster/proxy propagation. A qualifying deployment must establish a maximum **2,000 ms** from committed policy mutation to authoritative read visibility across every serving node/cache and prevent stale intermediary responses. Use full 200-response bodies with HTTP cache bypass; reject unvalidated `Age`, stale/proxy responses and 304/hash-only renewal. Source generation/order and request identity must match. Negative events invalidate immediately, but an event does not renew a positive grant unless its timestamp/propagation provenance is separately qualified; this bootstrap chooses no such positive event authority.

For missing, malformed, contradicted, unbounded or unqualified required fields, treat that source as unknown. Do not assign the 2 s allowance by assumption or silently use a large default. **Block the affected path** (or expire/leave an existing one) until the profile is qualified. For an arbitrary deployment whose bounds cannot be established, bounded native calling remains unsupported; non-call work can remain separately eligible. This is the selected safe behavior, not an invented API or a universal Nextcloud timing promise. Exact release and research-branch profiles stay separate.

## Numeric freshness and exposure

The same conservative schedule applies to each required account/configuration, membership/permission, consent/recording, E2EE and grid source in a qualifying local profile:

| Quantity | Selected maximum / behavior |
| --- | --- |
| `F` source age | **15,000 ms** |
| `R` refresh-start interval | **10,000 ms**, including scheduler/retry tolerance; normal starts 9,000 ms apart, with at most 1,000 ms scheduling slip |
| `D` request deadline | **3,000 ms**, including response body completion/validation; expired responses cannot renew |
| `S` propagation/cache allowance | **2,000 ms**, a prerequisite backed by profile evidence |
| `E` enforcement | **250 ms** after restrictive observation or grant expiry |
| Local capture/device release | **1,000 ms** after restriction/expiry/account-loss/leave observation; publication already closed within `E` |

`S + R + D = 15,000 ms <= F`. Refresh at most once per source every 9 s; no immediate retry burst. A failed refresh waits for the next allowed start while expiry remains armed. Server retry guidance may postpone requests, but **never postpone expiry**. Requests and their validation have reserved worker capacity; inability to meet the deadline causes suspension, not an interval extension. `Lease` implements `expiry = request_start - S + F`, using checked elapsed arithmetic, not receipt time plus F. Aggregation takes the minimum expiry over all required sources. A failure, partial body, matching hash, RTP packet or unrelated heartbeat resets nothing.

For an unannounced change under the qualified source assumptions, detection plus publication enforcement is bounded by `S + R + D + E = 15,250 ms`. Local device release is bounded by `S + R + D + 1,000 = 16,000 ms`. Independently, failure to renew stops publication by the old expiry plus 250 ms and releases devices by that expiry plus 1,000 ms. These bounds begin at server commit only under the qualified source assumption; account-loss shutdown begins at confirmed client observation, not unknowable remote revocation time. Known restriction/events invalidate immediately on receipt and enforce within `E`.

All timers use an injected monotonic clock with epoch plus elapsed milliseconds. No wall-clock timestamp grants freshness. The platform adapter must qualify elapsed-time behavior across sleep; suspend notification closes publication, invalidates clock/call continuity and stops capture. Wake creates a new epoch and evaluates invalidity **before** any media work; it cannot reset an expired lease. A missed suspend notification, detected clock regression/discontinuity, or inability to bound elapsed sleep invalidates all leases. `std::time::Instant` alone is not presumed to include platform sleep. Native sleep/resume and stalled-device behavior remain platform qualification requirements.

## Restriction precedence and half-open connections

1. Account/session identity validity and known room invariants precede capability/config/permission grants. `START_CALL` is needed when starting, not merely being a moderator; `JOIN_CALL` and per-stream permissions govern joining/publication. Unknown/conflicting restriction data blocks expansion.
2. A verified classified room cannot record, transcribe, expose forbidden content or bypass E2EE. Its documented Talk25 exception removes only inapplicable recording-consent prompting, even when the global consent setting is required. Require capability-backed recognized attributes and a noncontradictory room response; object name or preset label alone is insufficient. For ordinary rooms apply global required consent, or global optional plus room-required consent. A policy/call change invalidates old consent.
3. Required E2EE blocks joining/publication unless the native engine proves the expected protection, keys and participant/profile compatibility. No downgrade to transport encryption. Unknown/required encryption at expiry causes local leave. Unsupported recording/SIP/transcription/E2EE combinations are blocked, not guessed.
4. Known local enforced grid limit caps remote camera subscriptions and visible/decode surfaces. The initial local engine ceiling is 4 remote cameras and 1 screen per call, reduced by stricter verified policy; grid paging must unsubscribe hidden cameras. Counting screen versus camera under each server policy needs qualification. If the count semantics or source are unknown/stale, unsubscribe and blank **all remote video/screen** within `E`; retain audio only while its membership/consent/encryption gates are fresh. A grid change alone does not tear down authorized audio or activate a local device.

Control transport loss marks degraded immediately. Explicit HPB/internal session loss/removal invalidates session authority on observation, even if RTP flows. For a half-open connection with no explicit loss but failed refreshes, no existing lease survives its original expiry. Missing membership, consent or required encryption at expiry closes the local call; a grid-only source failure applies the narrower rule above. Never await remote leave to suspend.

Fresh policy after recovery may update availability, but cannot unmute, enable a camera or restart sharing. If continuity was lost or capture was stopped for policy/account loss/sleep, require deliberate rejoin and new call generation; preserve mute/camera intent and redo applicable permission/consent/security gates. Ringing never starts capture. Direct acceptance and deliberate Huddle/ordinary group audio entry run this gate sequence without generic device-prejoin; conference/webinar/presentation entry retains preparation under CALL-004. The header contract is defined in the conversation-dialog design, not inferred from a sidebar category.

## Local enforcement and failure

The alpha uses the maintained engine through the [media owner](005-native-media.md), in-process. The older account-helper/watchdog design is diagnostic history, not the shipping implementation. The core call state supplies expiring grants; media callbacks recheck the current call lifetime and publication deadline. Device ownership remains outside the renderer and engine.

Restriction, leave, account cancellation and policy expiry close local admission before remote leave. Queued application frames and audio are discarded, selected capture/output streams are stopped, and old generation callbacks cannot republish. Remote acknowledgment and local resource disposal remain distinct; a failed or unobserved release must not display “devices off.” Reconnection cannot silently restore a microphone, camera or screen after continuity was lost.

The product's 250 ms publication and 1,000 ms device-release targets remain verification requirements. The in-process binding does not establish the diagnostic helper's kill-on-stall containment, nor a universal bound for a hung native library or driver. Complete application fault, suspend/resume, packet and physical-device measurements are still required before claiming those bounds across supported platforms.

## Refresh costs and performance contract

The earlier planning model used five reads (`A/C/R/K/S`). The current local implementation additionally reads the call-participant list separately from connected participants, so a complete round has six source reads. Its traffic must be measured against the same product budget; the five-read estimate is not a result for the current app. Calls sharing the exact account/host can coalesce eligible `A/C`; per-room sources cannot be merged across rooms. Reserve 5 refresh slots/call (maximum 2 calls), with at most one request/source outstanding. Restrictive events invalidate at once and coalesce a refresh into the next allowed slot; they cannot cause unlimited request bursts. One-shot join uses the same allowance. No extra immediate retries are permitted. Signaling long polls/heartbeats remain additional measured traffic.

Earlier five-read planning estimate per round (not the six-source implementation): 16 KiB capabilities + 8 KiB room + 4 KiB participants + 4 KiB settings + 4 KiB account response + 10 KiB request/transport overhead = **46 KiB**; at 7 rounds, **322 KiB/min (~44 kbit/s combined)**. This is an estimate, not fetched payload measurement. Set a local policy-control envelope of **512 KiB/min combined per active call**; count TLS/retries and observe directional bytes. Responses retain the 256 KiB decoded hard limit. A profile that cannot refresh securely within its byte envelope must suspend and request reviewed budget/profile revision, never lengthen `F` or omit fields. Maximum byte consumption from a currently in-flight bounded response must be accounted separately when shutting down at the envelope.

Schedule one coalesced refresh wake and one earliest-expiry timer per active-call cohort, plus completion notifications. Planning allowance: ≤1 timer wake/s and ≤0.5% of one logical CPU per active call for policy control, to be measured. This leaves no assertion that cryptography/parsing is free. Include control in the existing audio/video traffic, CPU and package-power totals; the ~44 kbit/s combined estimate consumes part of the audio budget and needs real validation. An actual conflict requires independent Q.PERF review before measurement acceptance.

Signed-in idle with **no active call** has no 9 s call-policy polling; obtain fresh complete policy at a deliberate join. Routine chat/notification/room-list synchronization still follows its protocol and counts toward the ≤100 KiB/min and ≤10 timer wakeups/s idle budgets. Active-call refresh is counted in active-call workloads, not hidden as idle or excluded. Federated/guest profiles need their own reviewed request and byte accounting before enablement. No cost or performance pass is claimed.
