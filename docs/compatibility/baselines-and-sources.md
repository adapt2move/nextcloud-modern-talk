## Relevant baseline differences

| Subject | Reviewed Talk 24 / NC34 | Reviewed Talk 25 / NC35 | Product consequence |
| --- | --- | --- | --- |
| Preset creation | Default/forced, webinar, presentation, conditional voice room | Also channel, classified, and administrator-only announcement | Fetch the actual returned set; do not infer from major version |
| Reaction permission | `react-permission`; separate reaction bit | Same | A read-only-to-chat member may still react when allowed |
| Room attributes and owner operations | Voice-room attribute in reviewed baseline | Adds preserved/classified/channel/announcement and `promote-demote-owner` | Preserve unknown bits; implement restrictions before exposing affected actions |
| Organization settings | Tags, archive, importance/sensitive options as advertised | Also `unarchive` and `tags-show-unread` preferences | Only show settings present in current capability/config contract |
| Patch/backport examples | Docs place recording chunked upload, external-call-service config, and bot-features API under 24.0.1 | Docs place them under 25 | These are not inherently Talk-25-only features |
| Threads/pins/scheduling | Advertised in reviewed baseline | Advertised in reviewed baseline | Gate at runtime; do not postpone solely because of an NC34 label |

This table is a reviewed delta, not an exhaustive upstream changelog. [S03–S05] below support these findings. `classified` also carries retention and sensitive-handling rules; preserved does not prohibit every automatic deletion. External-call-service behavior is iframe-oriented, so it requires an explicitly separate browser-handoff decision in this native client.

## Preset and policy precedence

The S05 parameter merge is default → selected preset → user changes → forced parameters. S20's creation path then enforces classified invariants: public type becomes private group, listability becomes none and SIP is disabled; a nonempty object binding is rejected. Thus forced values do not universally win. CONV-003 requires the review to show understood effective constraints and reconcile the actual returned room before success. S04/S20 and S09's chat controller establish all-role channel call denial, moderator-only member lists, non-moderator announcement leave denial and preserved deletion/history/public-link/listability locks. These are distinct from editable preset defaults. Source-reviewed fixtures were read, not executed.

Classified exposure guards were checked in the [invitation service](https://github.com/nextcloud/spreed/blob/f35255ab86f31e8ee894641f6970a09ce4b90927/lib/Service/InvitationService.php), [bot controller](https://github.com/nextcloud/spreed/blob/f35255ab86f31e8ee894641f6970a09ce4b90927/lib/Controller/BotController.php#L470-L482), [Matterbridge controller](https://github.com/nextcloud/spreed/blob/f35255ab86f31e8ee894641f6970a09ce4b90927/lib/Controller/MatterbridgeController.php) and S09/S20/S21 (including summary/private-reply restrictions). These support specific API restrictions, not universal protection against plugins or participants. CONV-004 separately labels stricter native cache/preview/export policy. S21's Talk25 consent validator returns early for classified rooms even under global-required consent; CALL-009 retains required consent everywhere it actually applies and never treats this exception as permission to record.

The [call-end listener](https://github.com/nextcloud/spreed/blob/f35255ab86f31e8ee894641f6970a09ce4b90927/lib/Listener/ClassifiedRoomAutoDeleteListener.php) marks an otherwise unbound classified room for the [object-retention job](https://github.com/nextcloud/spreed/blob/f35255ab86f31e8ee894641f6970a09ce4b90927/lib/BackgroundJob/ExpireObjectRooms.php). `retention_classified_rooms` is a configurable room-retention interval (reviewed default 3600 seconds; zero disables that sweep), independent of preset message expiry. Preservation does not bypass this automatic deletion. The moderator [keep/unbind operation](https://github.com/nextcloud/spreed/blob/f35255ab86f31e8ee894641f6970a09ce4b90927/lib/Controller/RoomController.php#L1176-L1197) changes `classified` to `classified_persist`, excluding that room from the sweep and re-queuing after later calls; classified restrictions remain. Neither setting promises universal preservation or an exact deletion instant.

## Re-ring authorization and response discrepancy

S07's pinned API prose says re-ring requires a moderator and lists an already-in-call target as `400`. S21's **both-family implementation** instead checks effective `START_CALL`, call-enabled policy and current call/participant state. Its target service accepts local/federated user actors in the same room, suppresses notification if any target session is already in call, and rejects a local DND target with `400`/`status`. An already-in-call target returns without notification and the controller can return `200`. Missing/wrong-room targets return `404`; unsupported actor types produce `400`/`actor-type`. Federated notification/status handling also depends on the supported proxy/host path.

MOD-002/F-133 follow those effective-permission and target gates, without adding a moderator-only client restriction. CT-016 must confirm response semantics on each release/profile before a compatibility claim; source behavior is not a completed live test. Unknown recipient availability is not denial inferred from an offline icon, and a successful request never proves delivery or that the recipient heard a ring.

## Evidence limits and work still required

- No temporary Nextcloud/Talk servers, native media engine, Keychain adapter, or GPUI application were run for this research. All runtime claims remain unverified.
- Published patches above are initial release-test candidates. The lowest supported patch in each family must be declared and tested before a release claims all `34.x`/`35.x` deployments.
- API prose does not always enumerate newer controller routes. Before implementing a feature, reconcile its documentation with the pinned controller/request/response definitions and add contract fixtures; do not infer missing endpoints.
- Call acceptance/cancellation races, session/cookie establishment, native call E2EE, and provider-specific signaling require focused interoperability evidence. These are implementation gates, not unresolved product choices.
- Native access to arbitrary Smart Picker integrations, Matrix/bridge recovery, external iframe call services, and additional OS integrations remains conditional. No external shared secret is needed in the public specification.
- The design archive is supplementary evidence. These citations, not a copied snapshot directory or screenshots, establish upstream provenance. Updating a pin requires a recorded source diff and renewed review of affected tests.
